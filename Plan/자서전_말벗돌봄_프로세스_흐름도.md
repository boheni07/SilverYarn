```mermaid
    C --> D["청킹 + 메타태깅<br/>시간·인물·장소·감정·연결사진ID"]
    D --> E["임베딩 생성(BGE-M3)"]

    L --> M
    M --> N["구술체 → 문어체 정제"]
```

### 2.5 사진 기반 회고 → 챕터 인라인 편입 파이프라인 (신규)

가족 또는 당사자가 올린 사진이 대화의 소재가 되고, 그 결과물이 자서전 챕터에 자동으로 편입되는 전체 파이프라인입니다. 작가 모드·말벗돌봄 모드 어느 쪽에서 트리거되든 동일한 경로를 거칩니다.

```mermaid
flowchart TD
    U1["가족 웹 업로드"] --> Q["미회고 사진 큐 등록<br/>연도 태그 기반 예상 챕터 매핑"]
    U2["당사자 모바일 업로드<br/>(카메라 촬영·갤러리 선택)"] --> Q
    Q --> Sync["다음 Wi-Fi 동기화 시<br/>미회고 사진 큐 스마트폰 동기화"]
    Sync --> Session{"다음 대화 세션 시작"}
    Session --> Mode{"진입 모드"}
    Mode -- "자서전 작가 모드" --> Author["인터뷰 형식으로 사진 제시<br/>'이 사진 기억나세요?'"]
    Mode -- "말벗돌봄 모드" --> Care["자연스러운 회상 대화로 사진 제시"]
    Author --> Answer["음성 답변 수집 · 로컬 저장"]
    Care --> Answer
    Answer --> Link["사진 ID + 회고 음성/전사텍스트 연결"]
    Link --> Done["미회고 큐에서 제거(회고 완료)"]
    Done --> Upload["다음 Wi-Fi 동기화 시 서버 업로드"]
    Upload --> Engine["자서전 작가 엔진(2.1)<br/>사진 연결 청크로 인식"]
    Engine --> Exist{"해당 시기 챕터 존재?"}
    Exist -- "Yes" --> Update["기존 챕터 본문에 사진 자동 인라인 삽입"]
    Exist -- "No" --> New["신규 챕터 생성 후 사진 인라인 삽입"]
    Update --> Review["가족 웹 감수 대기열 등록(2.4)"]
    New --> Review
```

- **공통 트리거**: 업로더가 가족이든 당사자든 동일하게 미회고 사진 큐에 등록되어 별도 요청 없이 자동으로 다음 대화에 반영됩니다.
- **모드 무관 결과 일치**: 작가 모드의 인터뷰형 진행과 말벗돌봄 모드의 자연스러운 회상형 진행은 사용자 경험만 다를 뿐, 결과 데이터(사진+구술 텍스트)는 동일하게 자서전 작가 엔진으로 유입됩니다.
- **편입 원칙**: 별도 "사진 섹션"이 아닌 **해당 시기 챕터 본문에 자동 인라인 삽입**되며, 가족이 웹 콘솔(2.4)에서 위치·설명을 조정할 수 있습니다.

## 3. 모바일앱 — 온디바이스 STT/VAD/SLM/RAG 흐름

### 3.1 온디바이스 음성 파이프라인 상태 흐름

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> Listening: 웨이크워드/버튼 입력
    Listening --> VAD_Check: 음성 감지(VAD)
    VAD_Check --> Listening: 무음 지속
    VAD_Check --> STT_Processing: 발화 종료 감지
    STT_Processing --> IntentRouting: 온디바이스 STT 완료
    IntentRouting --> AuthorFlow: 자서전 모드
    IntentRouting --> CareFlow: 말벗 모드
    IntentRouting --> AssistFlow: 비서 모드
    AuthorFlow --> LocalTTS
    CareFlow --> LocalTTS
    AssistFlow --> LocalTTS
    LocalTTS --> Idle: 음성 응답 완료
    Idle --> [*]: 세션 종료
```

### 3.2 온디바이스 의도분류 · 모드 라우팅

```mermaid
flowchart TD
    Start["세션 시작(작가/말벗돌봄 모드)"] --> PhotoQ{"미회고 사진 큐<br/>존재?"}
    PhotoQ -- "Yes" --> PhotoPresent["사진 제시 + 회고 질문 발화<br/>(2.5절 공통 트리거)"]
    PhotoQ -- "No" --> Text
    PhotoPresent --> G["On-Device SLM: 회고 답변 생성"]
    Text["온디바이스 STT 결과 텍스트"] --> Router{"경량 온디바이스 라우터"}
    Router -- "회고/구술 키워드" --> A["로컬 질문목록 캐시 조회"]
    Router -- "감성/일상 발화" --> B["로컬 경량 VectorDB 검색"]
    Router -- "일정/복약 키워드" --> C["로컬 엔티티 파서"]
    A --> D["On-Device SLM: 꼬리질문 생성"]
    B --> E["On-Device SLM: 회상 답변 생성"]
```

> ※ 미회고 사진이 있으면 세션 시작 시 기존 질문목록·RAG 회상보다 우선 제시됩니다. 사진 회고 응답은 사진 ID와 함께 로컬 저장되어 2.5절 파이프라인을 통해 챕터에 인라인 편입됩니다.

### 3.6 설치모드 자동 분기 흐름 — 키오스크 / 일반 앱 (신규)

앱 설치 시점에 단말 사양을 자동 체크하여, 저사양·재활용 단말은 키오스크 모드로, 고사양 개인 단말은 일반 앱 모드로 설치합니다. 두 모드의 앱 기능은 동일하며 설치·잠금 방식만 다릅니다.

```mermaid
flowchart TD
    Start["앱 설치 시작"] --> Check["단말 사양 자동 체크<br/>RAM · Android OS 버전"]
    Check --> Judge{"사양 기준<br/>충족 여부"}
    Judge -- "기준 미달\n(저사양·재활용 단말)" --> Kiosk["키오스크 모드로 설치<br/>Device Owner/Kiosk Mode API 등록"]
    Judge -- "기준 충족\n(고사양 개인 단말)" --> Normal["일반 앱 모드로 설치<br/>홈 화면에 아이콘 추가"]
    Kiosk --> KioskLock["앱 단일 실행 상태로 잠금<br/>홈 화면·다른 앱 접근 차단"]
    Normal --> NormalIcon["다른 앱과 함께 아이콘 실행<br/>자유롭게 앱 전환 가능"]
    KioskLock --> Fixed["설치모드 고정<br/>(재설치 전까지 유지, 서버 원격 전환 없음)"]
    NormalIcon --> Fixed
    Fixed --> Register["기기 정보(기기ID·사양·설치모드) 서버 등록"]
    Register --> Onboard["온보딩(5.1)으로 진행"]
```

- **판별 기준**: RAM 용량, Android OS 버전 등 하드웨어 사양을 설치 시점에 자동 체크 — 구체적 임계값은 별도 기술 검토로 확정
- **앱 기능 동일성**: 키오스크 모드와 일반 앱 모드는 3대 운영 모드를 포함한 모든 기능이 완전히 동일하며, 설치·잠금 방식만 다름
- **고정 원칙**: 설치 시 1회 결정된 모드는 재설치 전까지 유지되며, 서버에서 원격으로 모드를 전환하거나 잠금을 해제하는 기능은 두지 않음 — 서버는 기기별 설치모드를 조회만 가능

### 5.6 동기화 실패 · 충돌 해결 프로세스

```mermaid
flowchart TD
    Sync["Wi-Fi 동기화 시도"] --> UploadCheck{"업로드 성공?"}
    UploadCheck -- "No" --> Retry1["지수 백오프 재시도<br/>(최대 N회)"]
    Retry1 --> UploadCheck
    UploadCheck -- "Yes" --> DownloadCheck{"다운로드 성공?"}
    DownloadCheck -- "No" --> Retry2["재시도"]
    Retry2 --> DownloadCheck
    DownloadCheck -- "Yes" --> Integrity{"체크섬 검증 통과?"}
    Integrity -- "No" --> Discard["손상 데이터 폐기<br/>재다운로드 요청"]

    Integrity -- "Yes" --> Conflict{"로컬-서버 버전 충돌?"}
```

### 5.7 사진 회고 협업 프로세스 (가족·당사자·서버 공통, 신규)

가족과 당사자 양쪽 모두가 사진의 출처가 될 수 있고, 그 결과가 자서전 콘텐츠로 자연스럽게 흡수되는 협업 흐름을 주체 중심으로 정리한 것입니다. 기술적 상세는 2.5절을 참조합니다.

```mermaid
sequenceDiagram
    participant F as 가족(웹)
    participant P as 당사자(스마트폰)
    participant AI as AI 서버

    alt 가족이 사진 업로드
        F->>AI: 사진 업로드 (WF3)
    else 당사자가 사진 업로드
        P->>AI: 사진 촬영·선택 업로드
    end
    AI->>AI: 미회고 사진 큐 등록(연도 태그 기반 예상 챕터 매핑)
    AI-->>P: 다음 Wi-Fi 동기화 시 미회고 큐 전달
    P->>P: 대화 세션 시작 시 사진 우선 제시(3.2)
    P-->>AI: 회고 음성·전사텍스트 + 사진 ID (다음 동기화 시 업로드)
    AI->>AI: 자서전 작가 엔진 처리(2.1) → 챕터 본문 인라인 삽입
    AI->>F: 감수 대기열 알림 (2.4)
    F->>F: 챕터 내 사진 위치·설명 조정(선택)
    F-->>P: 확정본 다음 동기화 시 반영
```
